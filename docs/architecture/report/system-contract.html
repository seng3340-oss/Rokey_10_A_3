누가 누구와 통신하나

Topic · Service · Action과 프로젝트 연결표

Action · 오래 걸리는 작업

목표(Goal)를 보내고, 진행(Feedback)을 받다가 결과(Result)를 받습니다. 제작·운반·그리기에 사용합니다.

Service · 한 번 요청·응답

입력(Request)을 보내 계산·설정 결과(Response)를 받습니다. 경로 계산·TCP 설정에 사용합니다.

Topic · 상태 알림

발행자가 상태를 내보내면 구독자가 받습니다. 개별 요청에 대한 응답은 아닙니다.

연결별 인터페이스

화살표는 요청 또는 발행 방향입니다. Action·Service 응답은 반대 방향입니다.

종류 / 타입보내는 쪽 → 받는 쪽용도
Action CakeOrder브릿지 BR → TM전체 제작 주문. 진행 단계·최종 결과 회신
Service GenerateTrajectoryTM → DP그림 좌표를 3D 경로로 계산
Action PickAndPlaceTM → RE케이크 픽업·작업대 배치·출고
Action GraspToolTM → RE펜 파지 또는 반납
Action DrawOnCakeTM → RE계산된 경로로 그리기
Topic TaskStatusTM → 브릿지 BR/task_status로 작업 상태 알림
Service SwitchTCP실행 측 보조 기능 호출·제공 노드 미정활성 TCP 변경. 타입만 정의
Service SetCompliance실행 측 보조 기능 호출·제공 노드 미정순응제어 설정. 현재 미사용

주문 하나가 처리되는 순서

① 웹 그림 전송 → ② 백엔드 저장·주문 전달 → ③ TM이 DP에 경로 계산 요청
→ ④ DP가 TM에 경로 반환 → ⑤ TM이 RE에 그리기 요청 → ⑥ 진행·결과 회신

케이크 운반·펜 자동 파지·출고는 확장할 공정입니다. 고정 케이크 MVP에서는 드로잉 연결을 먼저 검증합니다.

타입명 ≠ 통신 주소 CakeOrder 등은 데이터 형식의 이름입니다. Action·Service의 실제 ROS 이름과 네임스페이스는 노드 구현 시 정합니다. 백엔드↔브릿지는 내부 HTTP입니다. 기본 제작 Action 주소는 /cake/order이며 설정으로 변경합니다.

ROS 메시지 6종

Message(.msg)는 데이터 묶음입니다. Topic에 발행하거나 Action·Service의 필드로 넣습니다.

메시지 / 쓰이는 곳들어 있는 필드와 의미
DrawingPath CakeOrder.drawing_paths[]canvas_width, canvas_height: 해상도 surface: TOP / SIDE strokes[]: Stroke2D 획 목록
Stroke2D DrawingPath.strokes[]stroke_id: 획 번호 points[]: 원본 x/y 픽셀 좌표, z=0. 자동 끝점 연결 없음
CakeParams CakeOrder.cake_paramsradius / bottom_radius: 윗면·밑면 반지름 (m) height, board_width/depth/thickness: 실측 치수 (m) center: BASE 윗면 중심, reference_frame: base tool_orientation: 접촉 TCP 자세, orientation: 평면 방향(rad)
Waypoint3D 경로 계산 응답·그리기 Goalpose: 위치 (m)·자세 (쿼터니언) speed: 속도 (mm/s), pen_down: 펜 내림 여부 contact_force: 접촉력 (N), 높이 고정 시 미사용
WorkspaceCoords 고정 작업 위치 묶음cake_pickup_pose, workstation_pose, tool_holder_pose, delivery_pose cake_center, cake_radius, cake_height, cake_orientation approach_height, drawing_z_offset
TaskStatus /task_status Topicorder_id: 주문, phase: 단계, progress_pct: 진행률 current_command: 명령, message: 설명 timestamp: 기록 시각
좌표 규칙 화면은 px, ROS Pose는 m·쿼터니언입니다. RE에서 두산 API의 mm·ZYZ 각도(degree)로 변환합니다. center는 사용자가 접촉 확인한 TCP의 윗면 중심입니다.

요청과 응답에 담기는 값

생성된 Action·Service 파일 기준

Action 4종 · Goal / Feedback / Result

타입요청 · 진행 · 결과 데이터
CakeOrder목표: order_id, drawing_paths[], cake_params, tool_type 진행: current_phase, progress_pct, message 결과: success, error_code, error_msg, elapsed_time_sec
PickAndPlace목표: pick_pose, place_pose, approach_height, grip_width 진행: phase, progress_pct 결과: success, actual_place_pose, error_code
GraspTool목표: tool_id, action(GRASP / RELEASE), tool_pose, approach_dir 진행: phase, progress_pct 결과: success, error_code
DrawOnCake목표: waypoints[], drawing_surface, contact_force, speed 진행: current_stroke_idx, total_strokes, progress_pct, phase 결과: success, completed_strokes, error_code

Service 3종 · Request / Response

타입요청 · 응답 데이터
GenerateTrajectory요청: canvas_width, canvas_height, strokes_2d[], surface_type, cake_pose, cake_radius, cake_bottom_radius, cake_height, tool_orientation 응답: success, waypoints_3d[], pen_states[], estimated_duration_sec, error_msg
SwitchTCP요청: tcp_name 응답: success, current_tcp, error_msg
SetCompliance 현재 미사용요청: enable, axis[6], stiffness[6] 응답: success, error_code

필드를 읽는 기준

success는 해당 요청의 성공 여부, error_code / error_msg는 오류 코드·설명입니다. phase / current_phase는 단계, progress_pct는 0~100% 진행률입니다. pose는 위치와 자세, []는 배열입니다.
TCP는 펜촉 등 도구의 작업 기준점, grip_width는 그리퍼 폭(mm)입니다.
