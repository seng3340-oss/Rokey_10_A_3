그림과 주문 데이터

1. 웹 → 백엔드

POST /api/drawing · JSON · 한 요청에 한 면의 그림

필드의미
canvas_width / canvas_height캔버스 가로·세로 해상도 (px)
drawing_surface그리는 면: top(윗면) / side(옆면)
strokes[]손을 떼기 전까지 그린 획들의 배열
strokes[].stroke_id획 순서 번호. 0부터 시작
strokes[].points[]해당 획의 좌표점 배열
points[].x / y화면 왼쪽 위를 원점으로 한 픽셀 좌표

2. 백엔드 → 작업 관리 노드

CakeOrder Action · 제작 주문

필드의미
order_id백엔드가 생성한 주문 번호
drawing_paths[]그릴 면과 원본 획 데이터
cake_params케이크 반지름·높이·중심·방향
tool_type사용할 도구 종류

drawing_paths[] 안의 데이터

필드의미
canvas_width / canvas_height웹에서 사용한 캔버스 해상도 (px)
surface그릴 면: TOP / SIDE
strokes[].stroke_id웹에서 전달한 획 번호
strokes[].points[]원본 x/y 픽셀 좌표. ROS Point32의 z는 0
strokes[].is_closedfalse 사용. 획의 끝과 시작을 자동으로 잇지 않음

캔버스 크기와 원본 좌표를 함께 전달해야 실제 케이크 크기에 맞게 변환할 수 있습니다.

로봇 경로와 작업 상태

3. 작업 관리 ↔ 경로 계산 노드

GenerateTrajectory Service

필드의미
요청: canvas_width / height원본 캔버스 해상도 (px)
요청: strokes_2d / surface_type원본 획과 그릴 면 (TOP / SIDE)
요청: cake_pose케이크 위치와 방향
요청: cake_radius / height케이크 반지름과 높이 (m)
응답: success / error_msg계산 성공 여부와 오류 설명
응답: waypoints_3d[]계산된 로봇 목표점 배열
응답: pen_states[]목표점별 펜 내림·올림 상태
응답: estimated_duration_sec예상 작업 시간 (초)

4. 로봇이 따라갈 목표점 · Waypoint3D

필드의미
pose위치 (m) + 자세 (쿼터니언)
speed이동 속도 (mm/s)
pen_downtrue: 그리기 / false: 펜을 뗀 이동
contact_force목표 접촉력 (N). 높이 고정 방식에서는 사용 안 함

5. 작업 상태 · TaskStatus

/task_status Topic · 작업 관리 노드 → 백엔드

필드의미
order_id / phase주문 번호 / 현재 작업 단계
progress_pct진행률 (0~100%)
current_command / message현재 실행 명령 / 설명 또는 오류 안내
timestamp상태가 기록된 시각

위치 기준점, 두 면의 주문 묶음, 속도 우선순위, 취소·복구 방식은 추가 합의가 필요합니다. 상태 화면 연결도 아직 구현 전입니다.
