# 드로잉 통합 작업 공유

이 브랜치는 함께 문제를 확인하기 위한 작업 중인 코드다. PR이나 배포 완료 버전이 아니다.
최신 main의 PR #14 (`667fd64`, 일체형 선반·케이크 틀 가이드)을 반영했다.

## 포함된 작업

- `scripts/start_virtual.sh`, `scripts/start_real.sh`: 드라이버·업무 노드·백엔드·웹 통합 실행. 자세한 방법은 [실행 안내](START_SYSTEM.md).
- DP: 테스트2 기준 점 선별, 옆면 수평 원호·대각선 스플라인 경로 생성.
- RE: 직선·원호·스플라인 서비스 호출, 가상 첫 접근의 상승·후퇴 경유점.
- 가상 펜 모델·TCP와 TF 기반 빨간 잉크 표시. 물리 접촉 센서나 전체 충돌 검사는 아니다.
- 터미널 실시간 로그와 프로세스별 파일 저장, 반복 Ctrl+C에 대한 종료 처리.
- 기본 그리기 30mm/s, 비접촉 이동 80mm/s. 짧은 구간에서는 가감속·관절 제한의 영향을 받는다.

## 같이 확인할 문제

1. **새 station 모델과 드로잉 기준 연결**: 최신 기본 모델은 `station`이지만 자동 영점·잉크 중심은 이전 `legacy` 좌표 `(500, 0, 142)mm`를 기준으로 한다. 새 작업대에서 케이크 위치를 확정하고 모델·영점·잉크 좌표를 함께 맞춰야 한다. 기존 데모 표시에는 `layout:=legacy`를 사용한다.
2. **전체 주문의 연속 실행**: 첫 접근과 독립 파형 시험은 확인했지만, 임의의 여러 획·여러 주문의 연속 실행까지 검증하지 않았다. 옆면 손목 회전 한계와 짧은 구간의 속도 저하를 확인해야 한다.
3. **가상 접근과 실제 접근의 차이**: 상승·후퇴 관절 경유점 보완은 virtual/localhost 확인을 통과한 가상 모드에만 적용된다. 실제 로봇 접근은 별도 검증이 필요하다.
4. **ROS 검색 설정**: 외부 `ROS_DISCOVERY_SERVER`가 지정된 환경에서는 로컬 노드 검색이 막힌 사례가 있었다. 가상 실행기는 해제하고, 실제 실행기는 현재 교육장 설정을 유지한다. 실제 실행에서 대기 시 해당 환경변수와 `robot_description` 수신부터 확인한다.
5. **기존 검사 불일치**: `test_drawing_geometry.py`에는 웹 편집 여백을 반영하기 전의 좌표 가정이 남아 있다. 전체 검사 결과와 선별 검사 결과를 구분해야 한다.

## 기록

- 통합 후 빌드: `cake_decorator_interfaces`, `cake_decorator`, `cake_workcell_description`, `cake_workcell_bringup` 4개 통과.
- 통합 후 실행기·ROS·모델 검사: 150개 통과, 6개 실패. 실패는 위의 기존 `test_drawing_geometry.py` 좌표 가정 6건이다.
- 통합 후 새 station 배치의 전체 드로잉이나 실제 장비를 실행한 결과는 아니다.

- `results/`: 기존 legacy 배치의 독립 파형·FK·첫 접근 관측 결과. 새 station 모델 검증 결과가 아니다.
- `log/system/`: 로컬 실행 로그이며 Git에는 포함하지 않는다.
- 실제 주문 DB·토큰·개인 환경은 Git에 포함하지 않는다. 미확정 주문은 자동 재전송하지 않는다.
- HMI는 정적 예시 화면을 유지한다.
