# 원뿔대 케이크 옆면 중간선 테스트

일반 주문의 케이크 설정을 바꾸지 않고 별도 버튼으로 한 획만 검증한다.
사용자가 결과를 확인해 이상없다고 하면 임시 버튼·전용 로직을 제거한 뒤 PR을 만든다. 현재 단계에서는 PR을 만들지 않는다.

## 치수와 그리는 위치

- 윗면 지름 113.5mm, 아랫면 지름 120mm, 높이 79mm.
- 중간 높이는 윗면에서 39.5mm 아래다. 그 단면의 반지름은 `(56.75 + 60) / 2 = 58.375mm`다.
- BASE -X 방향, 즉 로봇을 향한 쪽을 중심으로 수평선을 그린다.
- 기본 길이 30mm, 웹에서 5~50mm로 선택한다. 길이는 직선 현 길이가 아닌 표면의 호 길이다.
- 펼친 옆면에서는 직선이고 실제 펜촉은 해당 단면의 원호를 따라간다.

중간 수평 단면에 한정하면 원뿔대와 평균 반지름 원의 궤적이 정확히 같다.
전체 케이크를 원통으로 바꾼 것이 아니며, 이 등가 반지름을 다른 높이나 대각선에 쓰면 안 된다.
일반 3D 미리보기·가상 케이크·접촉 잉크 표시는 기존 모델을 유지한다. 이번 기능은 별도 실측 치수의 테스트 주문이다.

## 실행

1. 기존 실행기를 종료하고 `bash scripts/start_real.sh`로 다시 켠다.
2. 교정된 펜촉을 **새 케이크의 윗면 중앙**에 가볍게 닿게 두고 YES를 입력한다.
3. 웹 아래의 **옆면 수평선 테스트**에서 길이를 확인하고 **옆면 테스트 실행**을 누른다. 캔버스에 직접 그릴 필요는 없다.
4. 이미 처리 중인 주문이 있으면 접수를 거절한다. 접수 번호는 로봇 작업 완료를 뜻하지 않는다.

접근 순서: 현재 영점 자세로 상면 위 상승 → 케이크 바깥으로 이동 → 바깥에서 관절 속도 10deg/s로 옆면 자세 전환 → 중간 높이 접근 → 표면 접촉 → movec 한 획 → 반지름 바깥으로 펜 떼기 → 상면 위로 복귀.
옆면 펜 방향은 기존 수직 아래 기준 30도를 유지한다. 순응·힘 제어는 추가하지 않는다.
각 동기 이동의 실제 TCP 도달을 확인하고 실패하면 다음 단계로 진행하지 않는다.

### 허공을 그리는 경우

실제 주문 `ORD-20261117-004`는 로봇이 경로 목표에 도달한 것으로 기록되었지만 사용자는 실제 펜촉 위치가 다르다고 보고했다.
당시 계산한 중간 원호 중심은 BASE `(393.769, -58.167, 465.117)mm`, 반지름은 `58.375mm`다.
코드의 Tool +Z는 펜촉 방향(안쪽·아래쪽), 그 반대인 몸통 방향은 바깥쪽·위쪽이며 수직 기준 30도로 계산됨을 검사했다.
부호만 뒤집으면 몸통이 오히려 안쪽으로 향한다. 실제 펜 방향이 Tool +Z와 맞는지, TCP가 실제 펜촉인지 확인하기 전에는 반전하지 않는다.
수직 상면에서는 기준점 영점으로 TCP 오프셋 문제가 가려질 수 있지만 자세를 바꾸면 오차가 나타난다.
후속 실행의 영점 기록에서 TCP 이름이 비어 있고 플랜지→TCP 거리가 0mm인 것을 확인했다. 실제 모드에는 TCP를 읽는 코드만 있었고 가상 모드와 같은 펜 TCP 등록이 없었다.
현재는 플랜지 기준이면 네 자세 접촉 측정과 새 TCP 등록을 먼저 안내한다. 자세 다양성·측정 오차를 검사하고 APPLY 후 실제 적용값을 검증한 뒤 케이크 중심 YES로 넘어간다.
사용자가 펜을 다시 잡았다면 `--calibrate-pen-tcp`로 새 교정이 필요하다. 코드와 합성 데이터 검사는 완료했지만 현장 교정과 실물 옆면 재검증은 아직 수행하지 않았다.

## 연결 방식

`POST /api/tests/side-midline`에 `{"line_length_mm":30}`을 보낸다.
일반 주문과 같은 SQLite 활성 슬롯·Idempotency-Key·브릿지 인수 절차를 사용한다.
테스트 주문의 `cake_json.test_recipe`에 실측 지름·높이·선 길이를 보존한다.
기존 ROS 메시지 필드는 바꾸지 않고, 테스트 주문에 한해서 `DrawingPath.surface`, `GenerateTrajectory.surface_type`, `DrawOnCake.drawing_surface`에 임시 값 `SIDE_MIDLINE_TEST`를 전달한다.
DP는 두 점·한 획·중간 높이·길이·로봇 방향을 확인하고 별도 경유점을 만든다.
일반 TOP/SIDE 요청은 이 분기로 들어가지 않는다.

## 검증 후 제거할 부분

- `config/side_midline_test.json`
- `frontend/src/components/SideMidlineTest.tsx`, `frontend/src/api/sideMidlineTest.ts`, 관련 테스트와 CSS, Kiosk의 컴포넌트 연결
- `backend/app/side_midline.py`, 관련 테스트, main의 라우터 연결과 orders의 테스트 치수 override
- goal_mapping의 `test_recipe` 분기, DP의 중간선 전용 변환·분기
- RE의 중간선 전용 실행·분기, Doosan 어댑터의 테스트 자세 전환 함수
- ROS 중간선 테스트 파일

일반 기능으로 형상 처리를 확장할지는 실물 검증 결과를 보고 결정한다. 테스트 성공만으로 실제 장비 전체 충돌 검증이나 다른 높이의 드로잉이 검증된 것은 아니다.

### 기존 수작업 측정값으로 시험하기

사용자가 제공한 네 자세의 계산 결과는 플랜지→펜촉 약 291.2mm, 최대 접촉 잔차 1.14503mm였다.
정밀 교정 기준 0.5mm는 그대로 두고, 이번 실물 시험에서는 별도 시험 프로필에 허용 잔차 2mm를 명시했다.
시험 프로필은 `config/local/pen_tcp_trial.json`에만 저장하며 Git에 포함하지 않는다. 실제 펜 고정 상태가 측정 때와 같을 때만 사용한다.

```bash
cd ~/ws_cobot_pjt
bash scripts/start_real.sh --pen-tcp-trial-profile config/local/pen_tcp_trial.json
```

실행기는 측정값·잔차를 보여주고 APPLY를 받은 후 새 TCP로 등록·선택한다. 네 자세를 다시 요구하지 않는다.
그 뒤 새 케이크의 윗면 중심에서 YES를 입력하고 웹의 옆면 테스트를 실행한다.
291.2mm 펜을 TCP 보정 없이 30도 기울이면 펜촉 높이가 약 `291.2*(1-cos30°)=39mm` 변한다. 이는 중간 높이로 내리는 39.5mm를 거의 상쇄할 수 있다.
시험 프로필이 실제 펜 정확도를 보증하지는 않는다. 현재 팔꿈치 역기구학 해를 유지하지만 로봇 링크 전체의 충돌 검증을 한 것은 아니다.
