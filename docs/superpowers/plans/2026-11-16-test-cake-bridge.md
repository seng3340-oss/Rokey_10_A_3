# 플라스틱 케이크 단일 주문·브릿지 구현 계획

사용자 요청: 측정 치수 반영, 윗면 중심 접촉 TCP 영점, 한 주문만 접수, 중복 방지, TM Action 전달.
기존 미커밋 보고서는 보존하고 이번 기능에 포함하지 않는다. 장비를 자동 실행하거나 기존 HMI를 연결하지 않는다.

1. 공통 JSON에 top=113.5, bottom=120, height=79, board=179×179×2mm 저장.
   프론트와 백엔드가 같은 파일을 읽고 3D에 경사 옆면을 표시한다.
2. 백엔드에 별도 실행 상태 테이블을 추가해 기존 주문 원본을 보존한다.
   BEGIN IMMEDIATE로 단일 활성 주문과 Idempotency-Key를 검사한다.
   기존 주문은 실행 여부를 모르므로 uncertain으로 보존하고 자동 전송하지 않는다.
3. 토큰 인증 내부 HTTP로 주문 인수·실행 이벤트·수동 불명확 상태 해제를 제공한다.
   인수·전송 시작을 저장한 후 Action을 보내며 재시작 시 자동 재전송하지 않는다.
4. Stroke2D.is_closed 제거. CakeParams에 아랫면 반지름·판 치수·기준 좌표계·TCP 자세를 추가한다.
   중심은 BASE 기준 윗면 중심, TCP 방향은 기록한 자세이며 케이크 표면은 수평을 가정한다.
5. ROS 브릿지는 YES 후 현재 TCP를 읽고 원본 획을 CakeOrder로 변환한다.
   백엔드와 통신은 전용 작업 스레드, Action 처리는 ROS executor가 담당한다.
   TM이 없으면 전송하지 않는다. 통신 불명확·재시작은 잠금을 유지한다.
6. 테스트 우선: 경쟁 접수·재시도·재시작·기존 DB·인수·결과 멱등성·오류·TCP 변환.
   임시 DB/가짜 TM으로 검증하고 실제 로봇 이동은 실행하지 않는다.
7. backend pytest, frontend test/build, ROS build/test와 가짜 TM 통합 검증을 완료한다.
